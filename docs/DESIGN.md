# 防窥盾 (Privacy Shield) — 设计说明

银行/券商员工的安卓办公应用里，员工经常在地铁、咖啡馆等公共场所查看客户资料和交易数据。
本模块用前置摄像头在**设备本地**判断屏幕前的人是否只有员工本人，并在有人偷看、有人举着手机
对准屏幕、或环境无法判断时自动遮挡敏感内容。

目标平台：Android 8.0+（`minSdk 26`），`targetSdk 34`。语言 Kotlin。

---

## 1. 先讲清楚：这个功能能做什么、不能做什么

**能做的**

- 在**正常室内光线下**，检测到屏幕前出现第二张朝屏幕看的脸时，约 0.6 秒内遮挡。
- 员工本人在镜头前换姿势、转头、眨眼、低头，不会误报（用轨迹跟踪 + 主人区域学习，而非逐帧人脸识别）。
- 环境光骤变（地铁进隧道、路人挡光、自动曝光跳变）期间冻结判断，不因光变而遮挡或解除。
- 摄像头被手/盖子遮住时**自动遮挡**（fail-closed）。
- 系统截屏、录屏、最近任务缩略图被 `FLAG_SECURE` 阻断——这是对付"举起手机拍照"的主要手段。

**不能做的（必须让业务方知道，否则会出事）**

- **正常的"拍照"是挡不住的。** 别人用另一台手机远距离拍、或用长焦镜头拍，屏幕内容会进他的照片。
  摄像头方案只能防"活人现场偷看"。对刻意偷拍，真正的防线是 `FLAG_SECURE`（本模块已开启）和
  MDM/DRM 层面的水印与防截屏策略。
- **无法区分"换人"和"本人离开一会儿又回来"。** 只有摄像头证据时，"员工放下手机走了、陌生人捡起来"
  与"员工转头 3 秒又转回来"在物理上不可区分。本模块的取舍见 §4「残差风险」。
- **戴帽子、口罩、逆光、强反光**会显著降低检测率；极端暗光下检测不可靠，此时进入遮挡兜底（PARTIAL）。
- **不是身份认证。** 它不验证"这就是王经理"，只判断"屏幕前是不是只有一名朝屏幕看的成年人"。

> 结论：这是一个**降低偶发泄露概率的可用性功能**，不是合规意义上的访问控制。不要用它替代
> 访问控制、水印、截屏策略或 MDM。在对外材料里不要写"杜绝泄露"。

## 2. 架构

```
┌──────────────────────────────────────────────────────────────┐
│ ui/ClientDetailActivity   ← 受保护页面，FLAG_SECURE            │
│   渲染三态: NONE / PARTIAL(打码) / FULL(不透明遮挡)             │
└───────────────▲──────────────────────────────┬───────────────┘
                │ GuardDecision                │ 用户操作(继续/验证身份)
┌───────────────┴──────────────────────────────▼───────────────┐
│ camera/ShieldHost  ← 绑定到 Activity 生命周期，onStop 必解绑      │
│   · duty-cycle 省电：无人时周期性开/关摄像头                     │
└───────────────▲──────────────────────────────────────────────┘
                │ FrameObservation (纯数据，无图像)
┌───────────────┴──────────────────────────────────────────────┐
│ core/engine/GuardEngine  ← 纯 Kotlin 状态机，可 JVM 单测         │
│   · 轨迹跟踪 → 主人判定 → 旁观者证据累积 → 光照/遮挡 → 迟滞输出   │
└───────────────▲──────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────────┐
│ camera/FaceAnalyzer  ← CameraX ImageAnalysis + ML Kit 人脸检测  │
│   · 只有 YUV 亮度面采样，无 Bitmap；帧用完立即 close()           │
│   · 无 Preview use case（用户永远看不到摄像头画面）              │
└──────────────────────────────────────────────────────────────┘
```

关键点：

- **决策引擎 `core/` 不 import 任何 Android 类型**，因此 23 个行为测试全部在 JVM 上跑，
  且结构上不可能有图像流入引擎。
- **数据只在内存里以 `FrameObservation`（几个数字/矩形）形式存在**，不含像素、不含人脸特征向量。
- UI 与检测完全解耦：引擎只输出 `ShieldLevel` + `ShieldReason`，UI 决定怎么表现。

## 3. 关键决策与取舍

### 3.1 用 ML Kit（bundled）而不是自训模型 / TFLite
- **bundled** 版模型打进 APK，**不依赖 Google Play Services，不联网**。对银行内网设备、
  定制 ROM 的机器这点很重要。
- 它提供 `headEulerAngleY`（头部偏航角），这是判断"是否朝屏幕看"的关键低成本信号。
- 用 `PERFORMANCE_MODE_FAST` + 无关键点/无轮廓/无分类，单帧推理在真机上约 10–20 ms。

### 3.2 为什么不用人脸识别（认脸）
- 认脸意味着要存生物特征模板 → 合规风险（个人信息保护法对生物识别有单独要求）、
  存哪都是隐患、且员工换发型/戴口罩就失效。
- 改用**轨迹跟踪 + 主人区域学习**：谁先在画面中心、持续存在、朝向屏幕，谁就是主人；
  其后用 IoU 连续性跟随，用慢速 EMA 学习主人常在的位置。员工换姿势由轨迹连续性消化，
  不需要任何生物特征留痕。

### 3.3 遮挡策略：文字置空，而不是模糊/马赛克
- 模糊可以被"从截图重算"或"从低质量摄像头稍微恢复"；置空不能。
- 遮挡期间视图树里也不放真实数据（重新渲染字符串资源），内存 dump 也拿不到。

### 3.4 光源鲁棒性（本需求最大难点）
- **只用亮度面 Y** 做光照统计（每帧几千字节读取，无 bitmap）。
- 帧间平均亮度突变（>22）→ 判定为曝光/遮挡瞬变，`unstableSuppressMs` 内**既不升级也不解除**，
  并扣减已累积的旁观者证据。
- 平滑后的亮度持续低于阈值 → `LOW_VISIBILITY`，降到 **PARTIAL**（可被用户"继续查看"临时关闭，
  避免在车里把员工锁死）。
- 平坦且极暗（mean≈5, stddev≈1）→ 判定为镜头被遮挡 → **FULL**（fail-closed）。

### 3.5 误报控制（员工换姿势不误报）
- 轨迹匹配用 IoU 或中心距离，姿势小幅变化仍匹配为同一轨迹。
- 主人区域用 `alpha=0.06` 的 EMA 缓慢学习，容忍持续的位置漂移。
- 新轨迹需 `bystanderMinHits=3` 帧、面积 ≥ 帧的 1%、且朝屏幕（|yaw|≤38°）才可能积累证据。
- 证据需**持续 600 ms**（灵敏度可调 350–900 ms）才触发；短暂路人（<600 ms）不触发。
- **升级快、解除慢**：约 0.6 s 遮挡，≥1.8 s 才解除，避免闪烁。
- 巨大反差：老板本人换座位不会触发，因为换座后主体仍是同一条轨迹。

## 4. 残差风险（务必与安全合规团队评审）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 远距离/长焦拍照 | 摄像头看不到、或看不到"脸朝屏幕" | `FLAG_SECURE` + 水印 + 机构级 DRM/MDM |
| "换人"不可区分 | 只有摄像头时，员工离开又回来 vs 陌生人接手无法区分 | 5 s 内视为本人；超时一律要求**设备凭据**恢复（§3.5、`ownerReacquireWindowMs`） |
| 戴帽子/口罩/逆光 | 检测率下降甚至漏检 | 作为已知限制声明；高风险场景配合 MDM 强制；日志可审计 |
| 强反射/眼镜反光 | 反光误判为"镜头" | 镜头检测**默认关闭**，且只增不减证据 |
| 员工主动关闭防护 | 用户可能嫌烦而关闭 | 设置页明确后果；临时关闭**记录审计日志**；机构可用 MDM 锁定该开关 |
| 摄像头被系统回收 | 其他 App 抢占前置摄像头 | `Status.UNAVAILABLE` → fail-closed 遮挡 |

`ownerReacquireWindowMs = 5s` 是本模块最重要的产品参数，**必须由安全团队确认**。
调大 → 更少打断，但"手机被捡走后被当成本人"的窗口更长；调小 → 更安全，但员工转头拿个东西
回来就要验密码。

## 5. 隐私保证（可验证）

1. **无 INTERNET 权限**：`AndroidManifest.xml` 用 `tools:node="remove"` 显式移除，
   即使依赖偷偷声明也会被剔除。实机验证：`dumpsys package` 只有 `CAMERA`，进程内 0 个 socket。
2. **不存任何图像**：流水线里没有 `Bitmap`；`ImageProxy` 在 `finish()` 里 `close()`，
   帧的生命周期只有一次检测。
3. **不存人脸数据**：主人模型是 RAM 里的矩形 EMA，进程/页面销毁即消失；不落盘、不跨页持久化。
4. **审计日志只有元数据**：时间、遮挡等级、原因、是否被 snooze。无图像、无人脸框、无人数、无位置。
5. **可见性与生命周期**：只绑定在受保护页面的 `onStart..onStop`；后台/最近任务/锁屏时摄像头**完全释放**
   （实机验证 `dumpsys media.camera` 为空）。
6. **CI 门禁**：`scripts/verify_privacy_guarantees.sh` 在 APK 上检查禁用权限，任一出现即失败。

## 6. 功耗

- 只在受保护页面运行，且 `onStop` 必解绑。
- 分析间隔自适应：遮挡中 120 ms / 有脸 300 ms / 空闲 1200 ms。
- 无人 20 s 后进入 duty-cycle：开 1.5 s、关 3.5 s（实机波形 `1111000011110000`）。
- 传感器帧率上限 15 fps（CameraX 无一等 API，用 Camera2 interop `AE_TARGET_FPS_RANGE`）。
- 单帧只做稀疏亮度采样（~4096 点）+ ML Kit FAST。
- **未做真机功耗测量**：不同厂商 ISP 在前置摄像头常开时的耗电差异很大。上线前需在目标机型上
  用 `dumpsys batterystats` 或 Perfetto 实测"连续查看 30 分钟"的耗电与发热，见 §8。

## 7. 可调参数

全部集中在 `core/engine/GuardConfig.kt`，并有 `init` 断言防止非法组合。灵敏度滑块映射见
`data/AppSettings.kt#guardConfig`（只调触发门槛，不动解除延迟，避免高灵敏度导致闪烁）。

## 8. 上线前必须做的验证（本仓库未覆盖）

本仓库的自动化覆盖了：决策引擎的 23 个行为测试、构建、权限门禁、以及模拟器上的
启动/相机绑定/检测/审计/生命周期/duty-cycle 验证。**以下必须在真机上做**：

1. **误报率**：≥20 名员工、各 30 分钟，在办公室/地铁/咖啡馆/出租车内四种光照下统计误遮挡次数/小时。
   验收建议：< 1 次/小时。
2. **漏报率**：脚本化"第二人从侧后方看屏幕"场景，统计检出率与延迟。验收建议：正面/侧面 ≤1 s，检出率 ≥95%。
3. **功耗/发热**：连续 30 分钟查看，对比开启/关闭防窥的耗电差；目标 < 5%/30min 额外耗电。
4. **机型矩阵**：至少覆盖前摄 FOV 差异大的几款（窄 FOV 机型侧后方人脸会出画）、
   无 GMS 的国产 ROM、折叠屏。
5. **口罩/帽子/逆光**的已知降级行为符合预期（是部分遮挡而非完全失效或持续误报）。

参数请按真机数据在这四项指标间重新标定，不要直接照搬默认值。
